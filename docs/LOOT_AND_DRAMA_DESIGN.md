# 武器战利品、名场面与持续成长设计

调研日期：2026-10-13。适用项目：All-Star Brawl。

**状态：设计提案，尚未实现。** 下列概率是首轮试玩参数；数学计算已核对，平衡与留存效果尚未验证。

目标体验：开场看到朋友的武器，想把它带回自己的收藏；对局中有机会打出能被朋友记住的名场面；结算后能看到明确进度，并有一个想再战的理由。

## 2. 首版采用三个互相衔接的系统

### A. 条件触发的“绝境名场面”

利用现有气势、绝招和格挡，让玩家主动创造触发条件。

- 单位是**整场三局两胜对战**，每名玩家最多一次判定机会。
- 在回合开始时生命不高于最大生命的 30%，并选择绝招；该绝招结算时获得一次 8% 的判定。未触发也消耗机会。
- 两人规则相同。机会跨小局保留消耗状态，再战一整场后恢复。
- 触发时该次绝招原始伤害增加 25%，但额外伤害不超过目标最大生命的 8%：`额外伤害 = min(round(原始伤害 × 25%), floor(目标最大生命 × 8%))`。
- 原始伤害与额外伤害相加后，仍按对手已锁定的格挡处理。双方伤害仍从同一初始状态计算，双 KO 规则保持一致。
- 两个人都触发时，各自播放演出；每次演出 1 秒，不额外获得行动回合。两人都满足条件时，一场至少出现一次的概率为 `1 − 0.92² = 15.36%`；实际总体频率因条件限制会更低。

| 角色 | 演出建议 | 让第一人称玩家感受到什么 |
| --- | --- | --- |
| IKUN | 起跳、球入画面、落点震动，“关键一球”字卡 | 篮球逼近视野，双方能看清暴扣与格挡结果 |
| 王司徒 | 羽扇扫过，墨字冲击与短促音效，“言语破防”字卡 | 视野边缘有文字冲击，核心血量和招式提示始终可读 |
| 吕布 | 画戟蓄力后横扫，停顿与火花，“天下无双”字卡 | 重量感来自前摇、武器轨迹和命中反馈 |

出招时显示是否触发，战斗记录能复述结果。所有新增镜头震动与闪光遵循现有减少动态效果设置。

**概率单位必须清楚。** 若每次攻击都有 5% 概率，一场攻击 20 次，出现至少一次的概率是 `1 − 0.95²⁰ = 64.15%`。本方案用每场有限机会保持名场面的辨识度。

### B. 越打越可能拿到对手的武器

普通切磋获得的是**可装备复刻版**：例如 IKUN 可以在下一场拿上吕布的方天画戟，原主人仍可继续使用。系统称为“武器拓印”，把普通朋友局的收集体验做完整。

规则：

1. 进入对局时展示对手携带的武器、你的收藏状态、本次获得概率和保底进度。
2. 每打完一场有效对战，双方各尝试一次，目标为对方**开场携带的武器类型**；胜负都推进武器收藏。
3. 失败次数按目标武器 ID 累计，跨小局、再战和对手保留。进入其他房间不清零。
4. 第 1～11 次有效尝试的当次概率为 **8%、12%、16%……48%**；第 12 次必得。
5. 获得后，该类型完成解锁，停止重复的基础武器抽取。已拥有武器的对局仍记录使用与宿敌战绩。
6. 保底只针对本次目标类型；开场锁定后不能临时换目标、换武器或重抽。

| 对该目标类型的累计有效尝试 | 本次获得率（此前均未获得） | 截至此时已获得的概率 |
| --- | ---: | ---: |
| 1 | 8% | 8.00% |
| 3 | 16% | 31.99% |
| 5 | 24% | 58.65% |
| 8 | 36% | 87.04% |
| 11 | 48% | 97.74% |
| 12 | 100% | 100.00% |

精确期望为 **5.14 次有效尝试**获得一个尚未拥有的目标类型。这里的次数不是所有游戏场数：只有遇到携带该目标武器的对手并完成有效对战才算。

条件获得率和累计获得率是两个概念。结算页显示“本次 24%；未中则下次 28%；最晚第 12 次获得”，不用“再打一把必出”等与实际规则不符的提示。

获胜且拿到拓印时，可记录“夺取”称号；输了拿到拓印时，标记“见招学艺”。来源与胜负真实记录，双方收藏进度都能前进。

### C. 武器带有来源和故事

收藏卡片显示：武器类型、提供拓印的对手、获得时间、该场比分，以及真实发生的名场面。

示例：

> 张三的方天画戟 · 第 6 次交手获得 · 2:1 逆转 · 天下无双被格挡

玩家下一次拿这把武器对战张三时，开场显示来源，制造“拿你的画戟打你”的社交动机。普通记录来自实际结算，不随机伪造逆转、胜场或来源。

基础武器首版保持相同战斗数值；变的是第一人称武器模型、音效、动作与来源。角色自身的生命和绝招仍按现有规则保留。允许组合诸如“吕布拿篮球”“王司徒挥画戟”，但新增装备不能让默认角色伤害随收藏数量增长。

三种武器很快就会收齐：已有一把的玩家，另外两个目标各约 5.14 次有效尝试，因此仅靠基础武器收集不足以形成长期内容。后续内容优先添加有取舍的新打法、可记录的高光战绩与外观熟练度，先观察玩家是否喜欢读招和朋友间复仇。

若以后引入不同武器数值，要把收益和代价绑定，并单独验证所有角色 × 武器组合。首版不把“数值看起来对称”当作平衡证明。

## 3. 真正夺走原武器的“夺宝局”

作为第二阶段的可选模式：双方开局前各指定一件可流转的战利品，明确展示所有权可能转移，双方确认后开始。

- 永久基础武器和角色解锁仍保留。
- 战利品所有权只在整场结束后结算，转移双方物品与记录需要一次原子存档。
- 首轮应使用**胜者确定获得约定战利品**的规则，避免同时叠加胜负风险、夺取概率和随机销毁三套机制。
- 抢来的武器能带上擂台，来源记录随流转保留；原主人有明确的复仇目标。
- 不将当前不具备账户与持久化的原型直接作为真实所有权转移的基础。

普通切磋与夺宝局的不同，会在房间入口和准备页明确展示。这是为满足不同朋友局风险偏好提出的设计；尚未进入首版实现范围。

## 4. 有效对战、存档与局域网约束

有效对战定义：完成一整场三局两胜，双方各至少有 3 次手动锁定招式，且没有中途掉线或退出。20 回合后的正常判胜可以计入；单个小局、超时自动格挡和反复建房不能额外生成尝试次数。

人机陪练用于练手，不结算其他玩家的武器拓印；入口展示这一规则。

首版允许朋友正常反复对战获得收藏。采用唯一 `matchId`，每名玩家每场最多结算一次；重复消息、刷新与重连不能再次领取已结算的奖励。

当前项目使用临时连接 ID，没有背包、长期玩家身份或存档。因此后续实现必须一起完成：

- 持久玩家身份与主机侧进度记录，明示收藏存在哪台主机上，换主机不会自动继承。
- 服务端判定随机结果与有效对战，客户端只显示概率、演出和收藏。
- 把解锁、失败次数和已结算记录一起保存；使用临时文件加原子替换，启动时校验存档。
- 身份与权限校验、未知武器拒绝、重复结算保护和断线恢复。

局域网朋友局的房主控制服务器和存档，无法保证对恶意房主、串通或改存档的强防作弊。首版收藏定位为本地主机上的朋友局进度；跨服务器排行榜和交易需要后续可信服务。

## 5. 界面应如何让玩家想再来一场

| 时机 | 展示内容 | 下一步动机 |
| --- | --- | --- |
| 准备页 | 对方武器和来源；“你的羽扇拓印：本次 20%，最晚还需 9 次” | 知道这场可能得到什么 |
| 战斗中 | 同步锁定、读招、低血量绝招机会 | 玩家自己选择冒险时机 |
| 名场面后 | 清楚的招式、格挡结果与伤害 | 能向朋友解释刚发生了什么 |
| 未掉落结算 | 胜负、战绩、本次概率、更新后的概率与保底剩余次数 | 看得见目标进度 |
| 掉落结算 | 武器近景、来源铭牌、“装备后再战” | 立刻尝试新组合 |
| 再战开场 | 双方换装与宿敌战绩 | 朋友之间能形成连续故事 |

名场面结算先生成确定结果，再按时间轴展示。武器揭晓演出不显示虚假的“差一点抽到”结果，也不通过重复点击改变已确定的奖励。

## 6. 实现顺序与试玩验证

建议下一个版本只落地：**三把可收集武器、按武器类型累计的透明保底、绝境名场面**。来源记录附在武器卡上，复用当前房间与再战流程。

改动将涉及 `shared/catalog.js` 的武器数据、`src/combat.js` 的条件随机结算、`src/server.js` 的身份/进度/幂等结算、`public/game.js` 的装备与反馈、存档及对应测试。先保证断线、重启和重复领取不会损坏收藏，再加入真正转移物品的夺宝局。

模型链路也必须一起修改：当前 GLB 将武器与身体合并在同一蒙皮模型中，需调整 `tools/make_characters.py`、Blender 源文件和 GLB 导出，把武器独立到手部挂点，才能让对手模型和第一人称武器同步换装；资源验证测试随之更新。

首轮找 6～8 名试玩者，每人体验 6～10 场，记录：

- 能否说清自己为何赢或输，以及名场面是否可读、可反制。
- 第一把目标武器需要几次有效尝试，是否理解当次概率与累计保底。
- 输掉后是否愿意再战、拿到武器后是否愿意装备并再战。
- 名场面的实际触发频率、增加的伤害是否改变过多胜负。
- 角色胜率、对局长度与断线率，同时注明样本量。

首轮试玩用来修正机制与参数；次日、七日回访率需要后续持续观察，不能由一场试玩或概率表推断。
